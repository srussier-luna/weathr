# Localization

## Follow the project's string system

| Found | Do |
|---|---|
| `.xcstrings` (String Catalog) | Edit the catalog. In SwiftUI, `Text("key")` literals are auto-extracted — keep using literals or `String(localized:)`, never bypass the catalog. |
| `Localizable.strings` / `.stringsdict` | Edit every `*.lproj` file that has the key. |
| i18n JSON / YAML (`i18next`, `react-intl`, `vue-i18n`, `next-intl`) | Edit each locale file. Keep ICU plural/select syntax intact. |
| `res/values*/strings.xml` | Edit each `values-xx` file. Keep `plurals` and format args. |
| Hardcoded strings, no system | Edit inline. Don't introduce an i18n system. |

Never hardcode a string in a view when the project has a catalog.

## Languages

- **Source language** (first in `languages`, or the catalog's source): rewrite with the ladder.
- **Each other existing language**: write a **native** version (see `native.md`) — not a translation of the new source string. Then mark it for review:
  - `.xcstrings` → set the localization `state` to `needs_review`.
  - Other formats (no state field) → list the keys in `NOTES:` (implementer) so the report names them as to review.
- Never add a language that doesn't exist yet.

## Keys

- **Semantic keys** (`delete.confirm.title`): keep the key, change the values.
- **Source-text keys** (SwiftUI default, where the English text *is* the key): changing the text changes the key and orphans existing translations. Don't rename silently:
  - Strings you just created → fine.
  - Existing ones → leave them, unless the task asks for the rename; then migrate (new key + carried/rewritten translations + removal of the old key).
- **Removed string** (rung 1): the key becomes unused. Removing it from catalogs is a structural change → only when the task asks for it; else say it in `NOTES:`. Check the key isn't used elsewhere before removing.

## Format arguments and plurals

- Preserve every placeholder (`%@`, `%lld`, `{count}`, `%1$s`) and its order constraints.
- **Never add a placeholder the call site doesn't pass.** "Delete “{name}”?" is better copy, but if the key had no `{name}`, the UI will print the braces. Propose it as a structural change (key + call site), don't slip it into the value.
- Use real plural rules (`.stringsdict`, catalog variations, ICU `plural`), never "photo(s)".
- SwiftUI inline `^[\(n) photo](inflect: true)` only inflects the noun, not verbs or adjectives around it. Use it only when nothing else agrees ("12 photos"). "sera/seront supprimée(s)", "will be/is" → catalog plural variations with full sentences.
- Rewording a pluralized string → rewrite every plural form in every language.
- Prefer formatters (`Date.FormatStyle`, `Intl`, `NumberFormat`) over words in strings for dates, numbers, prices, durations.
